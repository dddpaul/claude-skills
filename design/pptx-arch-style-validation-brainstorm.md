# pptx-arch-style — spec audit + .pptx linter

## Architecture decision

Two-phase improvement of the `pptx-arch-style` skill, sequenced strictly:

1. **Phase 1 — Spec audit (Class B errors)**: close every "point of invention" in `SKILL.md` so the spec becomes a complete source of truth (~120 precise values across coordinates, colors, fonts, borders, paddings).
2. **Phase 2 — Linter (Class A errors)**: a `.pptx`-level validator (`uv run lint.py deck.pptx`) that compares the produced artifact against the now-complete spec. YAML-driven rules. Hard `gate` in `SKILL.md` — no green report, no shipping.

The split exists because the empirical error catalog (extracted from the `038308b Improve pptx-arch-style` commit diff — every change in that commit was a real lesson) revealed two distinct failure modes: **Class A** (I knew the rule, used wrong value — linter catches), **Class B** (spec was incomplete, I invented — linter useless, only spec-audit helps). Phase 1 must come first; otherwise Phase 2's linter would scream at gaps in the spec rather than at real violations.

Target artifact for the linter: **`.pptx` file, not source code.** One universal validator covers both pptxgenjs (greenfield decks, per Anthropic's standard pptx skill) and python-pptx (surgical edits), because the produced XML is canonical regardless of generator. The linter complements (not replaces) Anthropic's existing visual-QA loop (render → PDF → JPEG → subagent inspection) — programmatic checks for exact values first, subjective layout review second.

## Components / flows

### Phase 1 — Spec audit

**Method:** structural read-through (A) then deck cross-reference (B).

- **(A)** Section-by-section pass through `SKILL.md` with a checklist of mandatory attributes per object type (shapes: x/y/w/h, fill, border, shadow, corner radius; text: face, size, weight, color, alignment, line spacing). Flag every `~`, `approximately`, `9-10pt`, `0.65–0.70`, every missing attribute.
- **(B)** Cross-reference a curated set of 7 generated arch-style decks across 4 projects (channels, equation/core, standard/stacks, datapower-v2). Process newest-to-oldest starting with `channels-definition-arch.pptx`; stop early on saturation. Unpack XML, enumerate unique `(shape_type, fill, border, font, size)` combinations. Cross-check against spec — any combination not derivable from the spec = either spec gap or deck violation. **Authoritative deck list lives in TASK-21 description** (single source of truth — do not duplicate paths here).

**Decision routing** for each gap (three buckets, marked in `decision` column):

- **auto-fill** — natural default exists from spec patterns (unspecified font → Arial; unspecified padding → 0.100in; unspecified border → 1pt; missing effect → `<a:effectLst/>` per Rule #11)
- **from-deck** — value not in spec but stable across real decks → adopt as de-facto standard
- **ask-user** — affects visual identity, no donor pattern (new color outside palette, new size outside 8/9/10/10.5/11/12/14/15/24/40.5/52pt, new distance not derivable from formulas)

**Artifact:** `design/pptx-arch-style-audit.md` — table `[SKILL.md section] | [ambiguous formulation] | [proposed concrete value] | [reasoning/source] | [decision]`. After user resolves the `ask-user` batch, all decisions are merged into `SKILL.md` in a single commit. `plugin.json` bumps minor.

### Phase 2 — Linter

**Stack:** Python 3 + `python-pptx` for reading. CLI `uv run lint.py deck.pptx`. Rules in YAML, separate from code, hand-editable.

**Layout:**
```
plugins/presentation/skills/pptx-arch-style/
├── SKILL.md                       (+ "Validation" gate section)
├── scripts/
│   ├── lint.py
│   └── tests/
│       ├── fixtures/
│       │   ├── golden.pptx        (100% conformant baseline)
│       │   ├── violators/         (one .pptx per violation type)
│       │   └── edge/              (tolerance boundaries, ambiguous matches)
│       └── test_lint.py           (pytest)
└── references/
    └── rules.yaml
```

Fixtures are generated by a small committed pptxgenjs script, not committed as binary blobs without source.

**Eight rule types** cover the empirical error catalog:

| Type | Catches |
|---|---|
| `mandatory_element` | Content → page badge + red line present |
| `forbidden_element` | Title/section → no page badge |
| `shape_coordinates` | Red line `x=0, y=0.500, w=10.000, h=0.042` |
| `fill_color` | Brand red `F12D16` ≠ `FF0000` |
| `border_spec` | Color + width + dashType per shape type |
| `font_spec` | Face + size + weight (Arial/Roboto Condensed) |
| `text_alignment` | Body left; titles per slide-type |
| `effect_override` | Every shape has `<a:effectLst/>` (Rule #11) |

**YAML rule format:**
```yaml
- id: red-accent-line-coords
  type: shape_coordinates
  applies_to: { slide_kind: content, shape_match: { fill: F12D16, h_lt: 0.1 } }
  expect: { x: 0.000, y: 0.500, w: 10.000, h: 0.042 }
  tolerance: { coord: 0.005 }
  severity: error
  spec_ref: "Rule #3 in SKILL.md"
```

`spec_ref` on every rule — when a check fails, the report points back at the exact spec line.

**Slide classification: explicit tag.** The generator must put `<!--arch-style:content-->` / `:title` / `:section` in speaker notes for every slide. Heuristic classification was considered and rejected as fragile. The tag requirement is added to the SKILL.md protocol; without it the linter emits a hard error per-slide ("untagged slide kind").

**Output:** text report grouped by slide:
```
[Slide 2 · CONTENT]
  ✗ red-accent-line-coords (error)
      expected: x=0.000, y=0.500, w=10.000, h=0.042
      actual:   x=0.100, y=0.500, w=9.800, h=0.042
      spec:     SKILL.md → "Rule #3"

Summary: 22 passed · 2 failed · 0 warnings
Exit code: 1
```

Exit codes: 0 = green; 1 = errors; 2 = warnings only. `--json` flag for machine consumption.

**Protocol gate** in `SKILL.md` (new "Validation" section, last in the document):

1. After every generation/edit of an arch-style `.pptx`: run `uv run scripts/lint.py deck.pptx`.
2. Exit ≠ 0 → fix violations, regenerate, repeat.
3. Only after green linter → proceed to Anthropic visual-QA loop (render → PDF → JPEG → subagent inspection).
4. Every slide must carry `<!--arch-style:content|title|section-->` in speaker notes.

## Scope cuts

- **No static code linter** (neither pptxgenjs nor python-pptx). Output-checker covers both runtimes by construction; AST-level static analysis for two languages was judged too expensive vs. value. Loses line-precise diagnostics; accepted.
- **No semantic checks** ("is this text about the right topic?"). Out of linter scope.
- **No aesthetic checks** (overlapping elements, balance, density). Owned by Anthropic visual-QA subagent loop, not by this linter.
- **No content QA** (typos, missing sections). Handled by `markitdown` + grep upstream.
- **No auto-fix mode** in v1. Linter reports; human (or Claude) fixes and re-runs.
- **No `pptx-core-style` coverage in this iteration.** Same approach could apply later, but kept out of scope here.

## Open questions

- **Tolerance defaults** for coordinate/size comparisons — `0.005in` is a starting guess. May need per-rule overrides (e.g., red line width `h=0.042` may render as `0.0419` after pptxgenjs round-trip). Calibrate during fixture creation.
- **EMU vs inches** in rule expectations — keep YAML in inches for readability; linter converts to EMU internally. Decision confirmed implicitly by the existing EMU Reference table in SKILL.md.
- **Cross-reference deck selection for Phase 1 (B)** — which actual `.pptx` files to treat as authoritative? `channels-definition-arch.pptx` (most recent) seems primary; equation presentations as historical reference. Decide at start of TASK-A.
