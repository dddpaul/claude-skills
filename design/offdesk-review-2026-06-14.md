## Reviewer Notes

1. **The headline issue is D-1.** The cumulative feature is functionally correct against the AC text but materially behind the canonical design intent on vault-path configurability. Addendum #1 was explicitly motivated ("misleading default", "no override mechanism") and was registered as authoritative. Shipping v0.1.0 with `~/Obsidian/android/` baked in means any future addendum-#1 follow-up will need to (a) rename the default folder (a one-time user-visible migration, with zero users this is free), (b) add `OFFDESK_OBSIDIAN_VAULT` env var support across push/pull/setup, (c) update the marketplace entry description, and (d) rewrite SKILL.md vault-path references. This is a real follow-up task, not a paper one. Recommend filing it now as TASK-5 with a clear AC set before this feature is closed out, and bumping `plugins/obsidian/.claude-plugin/plugin.json` version accordingly when the follow-up lands.

2. **AC-vs-addendum hygiene.** This drift is a process smell: addendum #1 was added to the brainstorm on the same day TASK-3 was scoped, but the AC text in `backlog/tasks/task-3 - ...md` was never updated to reflect it. The implementer correctly noticed the mismatch and made a reasonable judgment call (honor the AC literal), but the right move would have been to flag-and-pause for a brief AC rewrite. For future Ralph runs on this repo, consider adding a `feature:` label hook that diffs the design doc's addenda against the open task AC text and warns when they drift.

3. **`merge-frontmatter.py` quality is decent.** The script is stdlib-only, handles the three documented edge cases (no frontmatter, key-already-present in-place update, trailing newline), and is idempotent. Two small concerns: (a) `merge_keys` line `f"{key}: {value}"` does not YAML-escape the value — if `offdesk-source` ever contains a colon, quote, or other YAML-significant character (file path with `:` would be rare on macOS, but a path component starting with `-` or containing `#` is plausible), the resulting frontmatter could be malformed. The current call sites (project-relative path, absolute path, ISO timestamp) are unlikely to hit this in practice, but a brief inline comment noting the assumption, or a single-quote wrapping pass, would harden it. (b) The `missing = [k for k in OFFDESK_KEYS if k not in updates]` block is dead code — `updates` is always built with all three keys present in `main`, so `missing` is always empty. Either remove the check or move it earlier (defensive, but cosmetic).

4. **CLAUDE.md plugin-layout rule held up under load.** Adding a third plugin under `plugins/<domain>/skills/<name>/` without needing to touch CLAUDE.md is a small validation that the convention added during the marketplace-distribution work generalizes. Worth noting positively — no rule churn needed.

5. **Verdict rationale.** Aligned would require all canonical design intents satisfied; D-1 is too substantial (it's an entire addendum's worth of behavior). Drifted would require significant requirements missing, non-goals shipped, or substantial unexplained creep; the implementation correctly delivers 18 of 19 intents, has zero scope creep, zero non-goal violations, and the missing intent is documented as a follow-up. Partial is the right call: the feature ships a working v0.1.0 but is one tracked follow-up away from matching design intent.

**Recommended follow-up before declaring offdesk shipped:** file a TASK-5 ("Implement addendum #1: device-neutral default vault path + OFFDESK_OBSIDIAN_VAULT env var") that updates SKILL.md (push step 3, pull step 2, vault-path documentation near top of body), setup.md (laptop vault root, .stignore path), marketplace.json (description wording), and bumps `plugins/obsidian/.claude-plugin/plugin.json` to 0.2.0 (minor, since it broadens the configuration surface). With TASK-5 closed, this feature would move from Partial to Aligned.
